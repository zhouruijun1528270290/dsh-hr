# 题目来源、审计与开源边界

## 用户界面

面试提纲只展示题干、主题、题型、主备和必要要点，不展示面经标题、外部链接或题目来源统计。这样减少界面干扰，但不把“隐藏来源”当作授权或许可证替代品。

本地题库配置卡仍显示友好名称、启停状态和题目数量，便于用户确认本地数据是否可用。

## 内部记录

Host、preparation、session 和 SQLite 继续保存 `sourceRefs`、`sourceRevision`、来源状态与必要审计信息。它们用于：

- 冻结旧提纲和旧场次，避免后续题库更新篡改历史；
- 判断缓存、换题和题库更新；
- 按许可证或作者要求保留必要署名。

这些字段不进入 Live 面试官提示词，也不在提纲 DOM 中渲染。

`sourceUrl` 随精选题库 JSON 一并分发，仅用于本地审计：它不在界面展示，也不进入 Live 提示词。preparation 数据与 RPC 响应中可以看到这些审计字段（本机 Host 日志、浏览器调试工具里都能查到），这是有意保留的内部边界，不是公开页面展示。本文档随包分发（`package.json` 的 `files` 含 `docs`），作为包内可查的边界说明。

## 第三方题库

msy、面试鸭及其他第三方题库属于用户自己准备的外部数据：

- 插件只读取用户明确选择的本地目录；
- 不读取 Cookie，不自动联网采集，不写回源文件；
- 第三方 NDJSON、答案缓存、简历题库、个人材料和历史场次不进入 npm 包或开源仓库；
- `lib/data` 只允许插件自己的精选题库 JSON，发布测试对此设白名单。

用户公开分享、转载或商业使用第三方题目和答案时，仍需自行遵守对应内容的许可条件。

## 精选题与依赖

精选题按主题和常见面试考察点进行原创整理，不复述具体候选人的个人经历。需要改写时保留稳定的题目 id、topic 和 kind，并递增 revision；旧 preparation 和 session 仍使用原冻结快照。

本轮将 6 处过度具体的数量级或固定枚举改成通用原创场景；所有非 editorial 条目的 `sourceTitle` 去掉公司与面试轮次指认，统一为“公开面经参考 / 公开资料汇编参考”，原始 URL 只留内部审计。非 editorial 因题目或来源快照元数据变化统一 `revision: 2`；未改的 editorial 保持 1。题库条数、taxonomyVersion 与岗位分类不变。

Live2D、Pixi、PDF.js 等第三方运行文件继续保留各自许可证、来源说明和必要的 NOTICE。项目自身许可证与内容来源边界是两个独立问题，不因界面不显示来源而改变。
