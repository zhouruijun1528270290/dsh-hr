# HR 面试攻防

在 DeepSeek Harness（DSH）里按岗位和 JD 模拟面试。支持文字或语音回答、根据回答追问、保存历史场次和按需复盘。

## 在 DSH 桌面版安装

打开 **插件 → 添加插件**。GitHub 发布后，粘贴以下规格并确认安装：

```text
github:zhouruijun1528270290/dsh-hr#v0.1.0
```

也可以从 GitHub Release 下载 `dsh-hr-interview-0.1.0.tgz`，在同一入口输入安装包的绝对路径。本地候选验收使用此方式。启用后从侧栏打开「HR 面试攻防」，填写目标岗位，根据需要填写 JD 或简历，点击「准备面试」。首次使用可以选文字回答和静态头像。

插件按 `package.json` 的 `engines.dsh` 声明兼容范围。Windows DSH 桌面版用于首发验收。模型默认使用宿主当前账号，详见下方配置。回滚时先在插件管理器卸载当前版本，再从旧发布标签或备好的旧版 `.tgz` 安装，保留插件数据目录。

项目自有内容采用 [MIT](LICENSE)。第三方组件及素材见 [第三方声明](THIRD_PARTY_NOTICES.md)。

## 开发

开发和运行完整测试建议使用 Node.js 24 LTS 的近期版本（24.15 或更新）。插件运行时版本范围见 `package.json`。

```sh
npm ci
npm run build
npm test
npm run check
```

`client.js` 是发布标签随附的构建产物。修改 `src/` 或 `lib/contract.js` 后重新构建。PDF.js 4.10.38 的来源与校验值见 [PDF.js 来源记录](lib/vendor/pdfjs/SOURCE.md)。

## 材料上传

- 材料页支持选择 PDF、DOCX、TXT、MD，单文件最大 8 MiB；文件在本机 DSH Host 解析，成功后填入可编辑的简历正文。
- 上传不会自动保存，也不会复制原始文件；检查或修改正文后仍需点击「保存材料」。只有保存后的文字会在开始面试时进入既有模型上下文。
- 可根据明确的「求职意向」或带岗位后缀的文件名建议目标岗位，正文优先且不覆盖手填；低置信结果留空。该步骤完全在本机完成，不调用模型。
- 允许保存部分字段。填写目标岗位即可准备面试，简历和 JD 可以补充以便细化题目和追问。全部字段为空时保存按钮禁用并显示原因。
- 解析失败会保留当前编辑内容。扫描件或图片型 PDF 暂不执行 OCR，可按提示复制文字或后续接入 OCR。
- TXT/MD 支持常见 UTF-8/UTF-16 编码；DOCX 只读取正文所需的 ZIP/XML 成员，不执行宏、外部链接或隐藏文本。
- 解析结果最多 60000 字，超出会明确提示截断；PDF 最多读取前 40 页，采用单次请求总时限，Host 同时最多处理 2 份简历。
- 常见错误码：`resume-file-too-large`、`resume-pdf-encrypted`、`resume-pdf-scanned`、`resume-pdf-timeout`、`resume-busy`；原始文件内容和本机路径不写入错误详情。

## 市场题库与准备面试

- 面试准备页分为本场安排和题目时间线。未准备时先生成提纲；匹配时可直接入场或换一批题。备选默认折叠，点题目展开考察点，方向键与 Home/End 可以切换题目。
- 「换一批题」沿用当前提纲的考察方向与顺序。「换考察方向」按当前岗位和 JD 重选主问方向，候选充足时 15 分钟场换入 2 个，30 分钟场换入最多 3 个，同时减少连续重复。候选只有 1 个时换 1 个，候选用尽时保留提纲。每张题卡显示这道题在本场实际考察的方向。
- 「本场安排」下方可直接启用并预览 Live2D 面试官。「本场设置」保留时长、回答方式、语音、背景、凭据及本地题库管理。旧 Host 缺少提纲 RPC 时仍可直接进入动态面试。
- 本地精选题库包含 46 条参考题，其中 36 条为 Agent 题，10 条为软件岗位共享题。准备时先从相应岗位范围内查找能覆盖 JD 职责的题。简历用于现场回答与追问，简历深挖题不计入岗位职责覆盖。已有内容来源与 revision 继续保留在内部审计记录中。详见 `docs/content-provenance.md`。
- 有有效 JD 时以其中的职责为准。只填「Java 后端开发工程师」「Java 后端」或「Java 服务端」，或 JD 只是一段数字时，也可以按接口、数据库、幂等和故障排查匹配本地题；缺题时按岗位简称补查公开资料。
- 只填运维岗位时默认覆盖 Linux 服务、网络与 DNS、监控告警、容器及发布回滚，分别用职责关键词补题。Prometheus 采集 Kubernetes 的题计入监控职责。换题时优先使用可核实的面经，有覆盖缺口或面经备选不足时继续查找。
- 只填「工程师」「运营」「技术支持」等宽泛名称且没有有效 JD 时，先提供通用模拟情景。填写具体方向或 JD 后可按职责检索。提纲按题干去重，公开面经和模拟情景分别使用各自的题目和职责标题。
- 可在 Setup 通过系统目录选择器接入本机 msy 题库，也可显式点击「自动识别 / 重新扫描」；页面显示友好名称与题量，支持停用，取消选择不清空现有配置。手动路径仅保留在「高级设置」，目录只保存在本机。
- msy 连接器仍按 Agent 白名单只读导入本机文件，不读取 Cookie、不执行 msy 脚本、不写回源目录。详见 `docs/msy-source.md`。
- 本地有缺口时，插件启动 DSH 原生检索 Agent。Agent 先分析缺题职责，再使用宿主的网页搜索和读取工具，根据结果选择下一批关键词与平台。准备阶段会使用 DSH 当前的 Agent 模型和网页提供方。检索输入限于目标岗位和提取出的职责，不含简历、项目材料或历史回答。
- Agent 提交已读取的公开面经正文引文。只有通过面试经历和正文引用核验的题才标为「公开面经参考」。缺少面经时，Agent 按具体岗位情景补的题标为「模拟题」。刊载网址、原文短摘和证据版本保留在提纲快照里，核对过的题按岗位和职责缓存 14 天。
- 面经题干仅提供问法。岗位职责或明确的情景可用于补充模拟题，只有一条面经问法时不会套模板复制成模拟题。
- 「Java 开发」面经需有后端岗位证据才会收录，Android 题不进入后端提纲。公开资料不足时，后端、Android、嵌入式和餐厅服务岗位可以使用具体工作情景模拟。找不到可核实的具体职责又没有现成情景时，页面会说明使用了通用模拟。
- 15 分钟最多 4 道主问＋2 道备选，30 分钟最多 6 道主问＋2 道备选。主问优先覆盖不同职责；题量不足时按实际题量安排。「换一批题」优先选未见过的候选，按钮旁会分别显示换了几道主问和备选，题目会标出「已更换」。
- Agent 岗位和含经历深挖的提纲会把项目或工作经历介绍放在第一道主问。文字或语音转写回答可以触发临场追问，追问中的引文来自最近一次回答。后续涉及版本迭代、实际实现、线上排查或评测经历时，现场先确认，再根据回答深挖。没有相关经历或回答未确认时，改问对应的模拟情景。
- 压力面用更直接的措辞追问证据、反例和实际约束。模型引用的回答引文只用于校验，朗读直接接下一问。明确表示不知道、忘记了或答不上时，在追问额度内补问一次验证起点。仍答不上时，用简短的换题提示接下一道独立主问。朗读时可配合短停顿、疑惑语调或本机合成的轻叹音，并可驱动大肥鱼 Live2D 模型的眉眼、视线和头部动作。
- 材料、目标岗位、项目补充或时长变化后需要重新准备。未开始的旧版提纲升级后也需要重新准备。新版 Host 的普通面试先准备好与岗位匹配的提纲，面试时按提纲组织主问。已开始的场次继续使用冻结快照。
- 数据根目录下的 `market-role-evidence.json` 保存可重建的公开证据缓存。现有 `market.sqlite`、`market-sources.json`、`settings.json`、`preparations.json` 和 `preparations/<id>.json` 继续使用。

## 服务配置

DeepSeek Key 推荐在插件首页直接保存到 DSH 官方 credentials 服务；也可使用 Host 环境变量。界面只显示来源和可写状态，不返回完整 Key 或掩码，也不把明文写进面试记录或插件数据目录。

- 模型：默认复用 DSH 已登录的 `deepseek-account/deepseek-flash`，无需另填模型密钥；可用 `HR_INTERVIEW_HOST_MODEL` 改模型，或用 `HR_INTERVIEW_FORCE_HTTP=1` 切到独立 HTTP 网关。HTTP 配置为 `HR_INTERVIEW_MODEL_BASE_URL`、`HR_INTERVIEW_MODEL_API_KEY` 或 `DEEPSEEK_API_KEY`、`HR_INTERVIEW_MODEL_NAME`。
- DeepSeek ASR/TTS：在 HR 首页的「DeepSeek API Key」区域粘贴、保存并测试连接，保存后无需重启；也可只读回退到 Host 环境变量 `HR_INTERVIEW_DEEPSEEK_API_KEY` 或 `DEEPSEEK_API_KEY`。运行时先使用显式插件配置，再交给 DSH credentials 按官方优先级解析（启动环境 → 凭据文件 → 项目 `.env` → DSH `.env`）；凭据服务不可用时回退到当前进程环境变量。启动环境提供的 Key 只读，会遮蔽插件内保存。设置页可分别选择 DeepSeek 识别与朗读，音色为 `stella`（海星女声）或 `tide`（暗潮男声）。DeepSeek 使用专用 `/v1/tools/asr` 与 `/v1/tools/tts`，候选人录音会发送至 DeepSeek，原始音频默认不落盘。
- 本地 ASR：可复用官方语音输入 bundle 提供的 SenseVoice。安装并重启 DSH 后，在语音设置中准备 `sensevoice-local`；首次准备约需 1 GB 模型与运行资源。录音在浏览器转为 16 kHz 单声道 PCM16 WAV 后交给 Host，本地识别不发送音频到外部服务。
- ASR HTTP 回退：`HR_INTERVIEW_ASR_BASE_URL`、`HR_INTERVIEW_ASR_API_KEY`、`HR_INTERVIEW_ASR_MODEL`（默认 `whisper-1`）。
- TTS 回退：可使用浏览器 `speechSynthesis` 中文语音，实际音色取决于 Windows 已安装语音。通用 HTTP 配置为 `HR_INTERVIEW_TTS_BASE_URL`、`HR_INTERVIEW_TTS_API_KEY`、`HR_INTERVIEW_TTS_MODEL`（默认 `tts-1`）、`HR_INTERVIEW_TTS_VOICE`（默认 `alloy`）。
- 数据：默认 `~/.dsh/data/hr-interview`，可用 `HR_INTERVIEW_DATA_DIR` 或插件配置 `dataDir` 覆盖。

通用 HTTP ASR/TTS 分别使用 OpenAI-compatible `/audio/transcriptions` 与 `/audio/speech`，DeepSeek 不使用这两个路径。自动模式优先本地 ASR，其次通用 HTTP 和 DeepSeek；TTS 优先通用 HTTP 和 DeepSeek，最后使用浏览器。DeepSeek ASR 单段最长 120 秒、最大 8 MiB；界面在 110 秒自动收尾。明文密钥只在 Host 请求时读取；持久化由 DSH credentials 负责，插件自身不另存 Key。

## 直接语音回答

- 语音模式下按一下空格或「开始回答」按钮开始录音，再按一下结束；后台识别成功后直接提交，不再显示识别文字确认步骤。
- 焦点位于文字输入框、下拉框或可编辑区域时，空格仍用于正常输入；长按重复事件不会反复切换录音。
- 进行中的面试不展示 ASR 识别正文，语音回合只显示提交状态；识别文本仍由 Host 用于评分和复盘。识别为空或失败时可重说，文字回答始终保留。

## 复盘报告

- 生成复盘或打开已完成的历史场次时，直接显示独立的「复盘报告」；可通过「面试记录 / 复盘报告」切换，不再把报告追加到长面试记录之后。
- 报告采用浅色工作台，先展示本场结论和下次优先练习，再展示分项表现与逐题复盘。逐题复盘按原题合并追问，可展开看原回答、评分依据和改进建议。
- 报告显示七个维度的评分覆盖率。至少评了五项时显示训练参考分，按已评维度等权平均。明确的 0 分计入，缺评分项显示「未评估」。
- 报告区会显示等待生成、正在生成、失败可重试或没有有效回答等状态。打开生成中的报告时会读取最新状态，报告就绪后自动显示。
- 复盘保存在 `~/.dsh/data/hr-interview/sessions/<sessionId>/evaluation.json`，问答与状态分别在同目录 `turns.json`、`session.json`；知识点与回炉队列在数据根目录。

## 双屏面试间

- 进行中的面试页左侧为胸口以上近景 Live2D HR，右侧为候选人画面；宽屏左右各半，窄容器自动上下排列。近景以高度优先，允许左右对称裁切肩尾，避免窄面板重新退回全身。问题、transcript 与语音/文字回答控制保留在双屏下方。HR 与候选人角标统一使用深色半透明胶囊，避免浅色主题下白底白字。
- HR 虚拟背景提供「现代办公室」「会议室」「关闭背景」三种选择；两张背景为本机生成的 1344×768 WebP，经严格 `/hr-background` 白名单路由按需读取，无人物、无外部图片请求。背景只作用于左屏，带轻微暗角，关闭时保留原纯色；候选人画面不变。
- 面试页沿用浅色工作台。场次状态、主问进度和当前题目固定在双画面与历史对话的滚动区上方。进入新场次时回到顶部。作答与场次操作固定在下面，矮窗口缩小舞台。语音模式以「开始回答」为主按钮，文字回答默认折叠，语音识别不可用时直接显示文字输入。
- Windows 版 DSH 桌面的候选人区提供「开启本机预览」。插件包自带助手，通过 Windows 摄像头接口将画面显示在面试页右侧，无需另装软件。实时画面铺满右侧，关闭按钮浮在画面上。预览只使用最新一帧，画面只经本机回环传输并在内存中显示，无录制、文件保存或上传。关闭预览、暂停、结束、离开页面或连接中断会释放助手。无法启动时可用「打开 Windows 相机」独立预览。
- 网页版候选人摄像头默认关闭，点击后才请求纯视频权限，画面在浏览器内本地预览。关闭、暂停、退出或卸载会停止视频轨道；未取得视频权限时仍可继续文字或语音面试。

## Live2D 面试官（实验）

- 首页「启用 Live2D 面试官」默认关闭；开启后按需在 DSH 页面内加载 Cubism 4 / Pixi 运行时和本机模型，暂停或卸载时释放舞台。面试页使用提问、倾听、思考、空闲四种克制状态；DeepSeek 播放通过 Web Audio 真实振幅驱动口型，浏览器 speechSynthesis 使用明确受限的简化节奏，所有包络均按时间而不是屏幕帧率推进。
- 默认使用静态头像。可选配置 `live2dDir`（环境变量 `HR_INTERVIEW_LIVE2D_DIR`）指向已获授权的模型目录，并设置 `live2dCoreFile`（环境变量 `HR_INTERVIEW_LIVE2D_CORE_FILE`）为兼容的 Cubism 4 Web Core JS 绝对路径。修改后重启 DSH。
- Host 通过官方 `webServer` 暴露同源 `/hr-avatar` 与 `/hr-runtime`。模型路由只放行 model3 声明的 moc3、纹理、物理、显示信息和存在的 IDLE；运行时只放行三个固定版本 JS。两条路由均支持 GET/HEAD、realpath 防穿越，模型/运行时不可用时保留静态 HR 圆标。
- Cubism Core 和模型文件由用户自行获取。使用「DeepSeek-chan（大肥鱼）」时，遵照原作者的配布说明。见 [第三方声明](THIRD_PARTY_NOTICES.md)。
- 针对当前「大肥鱼」模型，运行时按 drawable ID 隐藏 `ArtMesh246` 与 `ArtMesh682` 两块异常黑色面片，保留另外三个鼻部阴影层；补丁只匹配该模型入口，不修改原模型，也不影响其它模型。

## 安装与回滚

只通过 DSH 官方插件管理器安装本目录构建产物，不手写 desktop profile。卸载插件即可移除入口；删除该插件的数据目录才会删除训练记录，卸载前先按需备份。

## 数据边界

默认保存材料、文本 transcript、时间指标与复盘；原始回答音频不持久化。报告中的分数是训练启发式，不推断真实工作能力、性格、情绪或录用结果。
